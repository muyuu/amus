# 音声メモ設計指針

## 概要

ゲーム中の発話を録音・書き起こし、ターンごとのメモとして蓄積する機能の設計を示す。

## 全体構造

録音・検知・書き起こしを独立した3層として扱う。録音は常時走り続け、その上にターン区間と書き起こしが乗る。

```
[常時録音リングバッファ]  ゲームが開始されている間ずっと回り続ける
        │
        ├─→ 層A: ホットワード検知    軽量モデル・常時・スライディング窓
        │         └ ターン境界を検出して区間を開閉する
        │
        └─→ 層B: 書き起こし          VADで発話を切り出し、逐次Whisperへ
```

層Aと層Bは同一のリングバッファを参照するだけで、互いに依存しない。検知層は
`HotwordDetector` トレイト越しに扱い、実装を差し替えられる。

## 常時録音

`VoiceRecorder` は固定長リングバッファとして音声を保持する。

- 形式: 16kHz / mono / i16
- 容量: 上限に達したら古い側から上書きする
- ゲームが開始されている間は回り続ける

録音はユーザーの操作対象ではない。ターンの区間を切り出すための土台であり、開始・停止は
ゲームの有無に追従する。UI に出すのはターンの開始・終了だけで、録音状態は表示しない。

バッファは**絶対サンプル位置**（録音開始からの累計サンプル数）で参照する。リングバッファ
上の物理位置ではないため、上書きによって位置が変化しない。上書き済みの位置を要求された
場合は、実際に返せる先頭位置を添えて残っている分だけを返す。

ターンのタイムスタンプ、発話区間、検知位置はすべてこの絶対サンプル位置から導出する。

## ターン

ターンは録音上の時間区間 `[start_sample, end_sample)` として表現する。録音の開始・停止とは
独立しており、1回の録音の中に複数のターンが並ぶ。

境界はホットワードまたは手動操作で確定する。

- 開始ワード検知時、前のターンが開いたままならその位置で閉じてから新しいターンを開く
- 最大ターン長を超えた場合は強制的に区切る
- 直前の区切りを取り消す操作を提供する

終了ワードは任意である。ターンは連続するため、開始ワードだけでも区間は途切れず確定する。

## ホットワード検知

リングバッファの末尾をスライディング窓で読み、トリガーワードの有無を判定する。

検知位置は絶対サンプル位置で記録し、書き起こし対象の区間からはワード自体の発話を除外する。
検知にレイテンシがあっても、バッファを遡ってサンプルを取得できるため区間の先頭は欠落しない。

誤検知への対処:

- 検知後のクールダウン中は同一ワードを無視する
- ターンが開いている間は開始ワードを無視する

トリガーワードは設定で変更できる。既定は「ターン開始」「ターン終了」。
設定時に以下を検証する。

- 4モーラ以上であること
- 開始ワードと終了ワードが音として十分に離れていること
- プレイヤー名・部屋名と衝突しないこと

設定画面には、実際に発声して検知されるかを確認するテスト機能を置く。

## 書き起こし

ターン区間内の音声をVADで発話単位に切り出し、逐次バックグラウンドスレッドへ送る。
ターン終了を待たずに処理することで、会議フェーズに入った時点でメモが揃っている状態を保つ。

タスクフェーズの発話は短いキーワード中心であり、1チャンクあたりの処理量は小さい。

## 認識精度

### プロンプトのトークン予算

Whisper の `initial_prompt` は **224トークン**（`n_text_ctx` / 2）が上限で、超過分は
**先頭から切り捨てられる**。プロンプトはこの予算内に収める。

構築は優先度の低いものから並べ、重要な語ほど末尾に置く。

```
部屋名  →  ゲーム用語  →  プレイヤー名
（溢れたら切られる）        （必ず残る）
```

- トークン数は `WhisperContext::tokenize()` で実測し、予算を超える分は優先度の低い側から落とす
- ラベルや説明文は置かず、単語の羅列とする。プロンプトは直前の書き起こしの続きとして
  解釈されるため、説明文はトークンを消費するだけで効果がない
- 部屋名は代表表記のみを載せる。別名・英語表記は語彙補正側で扱う

### 語彙補正

プロンプトは出力を保証しないため、書き起こし結果を既知語彙で補正する。

```
Whisper出力  →  読みに正規化  →  既知語彙と近似マッチ  →  正規表記へ置換
```

既知語彙はプレイヤー名・部屋名・ゲーム用語で構成する。候補数が限られているため、
近似マッチの誤爆は起きにくい。特にプレイヤー名は候補がゲーム参加者に限定される。

この「読み正規化 + 近似マッチ」はホットワード検知にも用いる。トリガーワードの表記ゆれを
同じ仕組みで吸収する。

## 設定項目

| 項目 | 内容 |
|---|---|
| トリガーワード | 開始・終了ワード。検証とテスト機能付き |
| 最大ターン長 | 超過時に強制的に区切る |
| リングバッファ容量 | 保持する録音の長さ |
